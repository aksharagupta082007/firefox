# AURORA TECH — System Architecture & Implementation Specification

## 1. Executive Summary
AURORA TECH is a production-grade, autonomous disaster intelligence platform designed to orchestrate emergency response in real-time. Unlike traditional chatbots, AURORA is a vertically integrated cognition engine that ingests multimodal distress signals (text/voice), extracts structured intelligence using LLMs, and manages tactical resource allocation via a state-consistent multi-agent workflow.

## 2. Technical Stack
- **Backend Framework**: FastAPI (Asynchronous Python 3.12+)
- **AI Orchestration**: LangGraph (State-machine driven multi-agent workflow)
- **LLM Gateway**: Dual-provider system (Gemma 4/Gemini via LangChain for cloud, Ollama for edge fallback)
- **State Management**: 
  - **Shared Operational Memory**: Redis (Concurrency-safe list updates & atomic locking)
  - **Persistent Geo-spatial Data**: PostgreSQL with PostGIS extension
- **Multimodal Services**: 
  - **STT**: Faster-Whisper (Low-latency speech-to-text)
  - **TTS**: Piper (Ultra-fast local text-to-speech)
- **Real-time Communication**: WebSockets with Redis Pub/Sub broadcasting.
- **Security**: JWT-based Authentication with Role-Based Access Control (RBAC).

## 3. Core Architecture & Components

### 3.1 Autonomous Agent Orchestration (LangGraph)
The system's core "brain" is implemented as a directed acyclic graph (DAG) that ensures state consistency across distributed reasoning steps.

| Node | Responsibility | Logic / Model |
| :--- | :--- | :--- |
| **Triage Agent** | Intelligence Extraction | Converts raw SOS (text/voice) into structured JSON (severity, victims, injury summary). |
| **Tactical Agent** | Deployment Reasoning | Interacts with PostGIS and Redis to find nearest responders and hospitals; suggests 3 priority actions. |
| **Oversight Agent** | Strategic Synthesis | Aggregates global state into high-level briefings and system efficiency scores for the Admin console. |
| **Update State** | Operational Persistence | Atomic commits to Redis and PostGIS; triggers real-time WebSocket broadcasts. |

### 3.2 Human-In-The-Loop (HITL) Governance
To ensure safety in critical deployments, the LangGraph is wired with **mandatory interrupt checkpoints**. 
- The system pauses execution after the Tactical Agent's proposal.
- State is persisted via a `MemorySaver` checkpointer.
- Admins must manually approve or reject the deployment via the `/api/admin/approve` endpoint before the graph resumes and dispatches the responder.

### 3.3 Multimodal Infrastructure
- **Voice SOS**: Supports binary streaming and Base64-encoded audio. Transcriptions are injected directly into the triage pipeline.
- **Semantic Memory (RAG)**: Implements an operational aggregation layer. Historical incidents are summarized to prevent context window saturation while maintaining long-term situational awareness.

## 4. Functional Interfaces (RBAC)

### 4.1 Admin Command Center
- **Bird’s Eye View**: Real-time map of active incidents and responder positions.
- **Strategic Briefing**: Executive summaries generated by the Oversight Agent.
- **Approval Gate**: Interface for reviewing and authorizing AI-suggested tactical deployments.

### 4.2 Responder Tactical Dashboard
- **Dispatch Orders**: Real-time push notifications via WebSockets.
- **Tactical Briefs**: Contextual information about the assigned incident (severity, victims, etc.).
- **Safe-Route Logic**: Integration with tools to detect road blockages and suggest alternate paths.

### 4.3 Citizen SOS Portal
- **Low-Latency SOS**: Fast text-based emergency reporting.
- **Voice Emergency Mode**: Push-to-talk voice SOS with real-time transcription feedback.
- **AI Triage Chat**: Automated guidance during the initial distress phase.

---

## 5. Security & Concurrency Safety
- **RBAC**: Strictly enforced roles (`admin`, `responder`, `citizen`) ensure that only authorized personnel can approve dispatches or view high-level summaries.
- **Concurrency**: All shared state mutations (Redis) use atomic `LPUSH`/`LTRIM` pipelines and distributed `SET NX` locks to prevent race conditions during heavy incident volume.

## 6. Deployment Requirements
- **Environment**: Python 3.12+, Node.js 18+, Redis 6+, PostgreSQL 14+ (PostGIS enabled).
- **Critical Dependencies**: `fastapi`, `langgraph`, `langchain-google-genai`, `ollama`, `redis`, `sqlalchemy`, `faster-whisper`.
- **API Keys**: `GOOGLE_AI_API_KEY` (Required for Gemma 4 Cloud).
